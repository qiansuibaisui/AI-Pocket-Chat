# zcode 需求文档 v3（终版）

基于实测台账（F1-F4、B5/B6、H1-H3、E6 及本窗口全部记录）整理。所有失败项原测试脚本保留在台账，修复后按原判据干净复测即可翻案归档。

## 第 0 项 · 工程前置

- **签名路线**：自建正式 keystore 统一签名；首次从作者版切换需卸载重装 + 数据导出导入，此后覆盖升级无损；备份指引随交付附上；
- **数据库 migration 纪律**：凡 schema 变更必须写 migration 逻辑，禁止裸读新表结构（唯一真实数据丢失风险路径）；
- **git 纪律**：fork 仓库、zcode-mod 分支、“新增文件优先 + [zCODE] 注释标记 + 最小 diff”三纪律；
- **解析容错规则**：任何模型输出先经容错层清洗（正则剥离泄漏的 `[/dialogue]` 类标签、锚点块解析容错）再进入下游——这是模型分配矩阵自由的前提；
- **升级合并 SOP（目标⑤）**：fetch 上游 → merge 进 zcode-mod → 冲突裁决（模块化纪律压小冲突面）→ keystore 签名打包 → 覆盖安装。关注作者更新日志，官方修复即撤销对应自改项（已执行案例：日记重生成死循环，官方已修，撤销，归档官方修复清单 +1，遵守第 0 项纪律）。
- **长命令后台化纪律（2026-09-08 追加，实测教训）**：所有预期超过 2 分钟的命令（assembleRelease、全量单测、R8）**必须后台执行 + 日志落盘轮询**（输出重定向 `> build_log.txt 2>&1`，轮询该文件判进度），禁止前台同步等待。前台长等会造成任务通知中断、误判"死循环"而盲目重试；重试前必先 `tasklist` 查存活 java/gradle 进程与 `.gradle/**/*.lock` 实证锁状态（2026-09-08 一次误判实录：所谓死循环实为零存活进程，仅通知中断）。

## 第 1 项 · 429/Timeout 加固 + 幂等重试（目标④）

- 超时常量 + 指数退避重试（地基）；
- **幂等约束**：重试前校验上一版是否已成功落盘，已落盘则丢弃重试结果；
- **冲突去重**：同一邀约/开场短期内多次生成，保留最新作废旧条目，禁止“已接受 + 已婉拒”矛盾状态并存落盘（实证在案）；
- **429 处理**：识别限流响应码，退避等待而非立即报错丢弃；
- **顺带运维项**：压测期间跑观测台对照，验收后台分析模型（DeepSeek v4-flash）产出质量（数值合理性/四场参数漂移），并搞清“预算 0/40 但有更新”“命中/意图为空”两处机制。

## 第 2 项 · 锚点中央登记制（目标①，最高优先级，一切的地基）

**病灶证据链（全部实测）**：贝克曼“近况页：寝室熟睡 vs 对话：甲板守夜”（周边系统不消费对话锚点）；基德名片与酒馆场景平行漂移；H1 角色自创锚点字段；E6 对话内锚点实时跟随（酒馆→移动中→街道→港口）；佩罗娜线证明聊天→锚点管道响应 ≤1 分钟，但锚点→日程完全割裂（锚点在海上，日程生成整套陆地生活）；MiniMax 切换导致锚点链断裂（锚点实为模型协作协议，依赖格式服从性）。

**需求**：建共享剧情状态存储层，**锚点 = 系统实时登记、全系统只读消费**：

### 状态结构

当前事件 + 受影响卡名单 + 各卡独立位置（白团靠岸 ≠ 佩罗娜靠岸）+ 已完成事件/已执行流程登记（治剧本重演——见面结束后私聊三次回滚切磋现场、整套收尾流程重演并时间回退，根因即“模型无法区分已做/未做”）；

### 写入方

1. 对话内锚点块落库（现有格式，收尾时落库）+ **写入兜底**：本轮模型未输出锚点块时自动延续上一快照并轻量提示补齐（锚点链与模型解耦，换任何模型不断链）；
2. 导演事件（第 5 项）；
3. 用户手动修正（第 3 项管理台）；

### 读取方（核心，强制接入五处）

1. **对话锚点注入**（现有功能的持久化版）+ 近期已完成事件清单注入（对话生成时声明“以下流程已执行完毕，不得重新执行”）；
2. **日程生成**——位置约束：锚点在海上 → 禁止陆地活动条目（F1）；来源分级约束：见面模式确认 > 对话明确约定 > 聊天随意提及，末档禁止进入正式日程（治幻影见面：艾斯“集市吃饭”日程 + 朋友圈“正在吃”实锤）；顺带修复格式双写（「和「千岁」和千岁在集市」）与日期归属错误（当天聊天被标“昨天”，验证点：佩罗娜明早日程）；
3. **朋友圈生成**——发布位置字段强制读取锚点，海陆错配拒绝生成（F1 验收①）；跨角色互动前校验双方位置，不同锚点不得互动（F1 验收②）；
4. **名片状态/近况**——改为锚点派生显示，不再独立生成（治贝克曼式脱节）；
5. **日程补丁**——重大世界事件触发受影响卡日程插入/修正（复用 App 已有“事件层星标插入”机制，通道从“仅邀约”扩展），治“明天靠岸却滞留”；
   - 节点命名规范化（杜绝“靠港中/停泊中/航行中”漂移混用）；

### 设计原则

状态由系统生成，模型只读不写；

**附注（回流豁免条款）**：官方 [系统记录] 若升级到结构化事件清单级别，第 4 项的见面回流自改降级为格式对接（艾斯侧 [系统记录] 验证结果待定）。

## 第 3 项 · 人际关系与锚点管理台（目标②）

**需求**：自动调整为主 + 手动覆写为权威的双模式管理界面。

- **读侧**：每卡视图 = 质感四维 + 曲线、跨团关系、知晓层级矩阵行、当前锚点、近期事件时间线；
- **写侧（手动 = 最高优先级）**：手动调整/改写/回滚，系统不得改回自动值；手动值打标记与自动值分开存，自动漂移发生在手动基线之上；带时间戳历史 + 版本回滚；
- **自动通道**：锚点输出落库、剧情事件 → 知晓层级翻转、互动累计 → 角色×角色质感漂移、出场统计 → 疲劳衰减表；
- **防幻觉污染**：关键写入（“单向知晓 → 亲历”翻转）需正文明确事实或导演注入背书，角色吹牛不改矩阵；
- **关系双轨**：角色×用户 = App 原生负责（含观测台 8 维/敏感度矩阵，zcode 只读镜像）；角色×角色 = 自动漂移工作区（App 盲区）；
- **认知矩阵**：按《角色认知边界》三代样本兼容（亲历/转述/单向知晓），自动提取“谁在场/谁得知什么” + 手动修正双轨；
- **P3 专项验收**：手动锚点修正的跨日留存（“后天起航”场景：手动 patch 后第三天检查贝拉是否还记得——日记书写权单通道导致非主角卡纠偏无持久化落点，本管理台即为落点）。

## 第 4 项 · 主动消息全面治理（目标⑥）

**病灶证据**：F4 两次失败（提示词模块根本不在生成路径内加载）；H2 三连败（陌生卡主动发消息、单向知晓朋友圈互动）；日程误认（角色把自己日程当用户行为）；观察项在案（佩罗娜“听说你在喝淡可可”信息来源不明，若确认经朋友圈反向读到不可见信息，本项加读侧信息来源合法性校验）。

**需求（管道层手术，生成路径内注入）**：

- **接地注入**：发射前强制注入当前锚点 + 最近 N 条对话摘要 +（第 2 项建成后）当前剧情节点；
- **日程归属标定**：注入块明确标注“以下为 {角色名} 本人日程，与 {{user}} 无关” + 附 {{user}} 最近已知位置；
- **关系门槛**：发射前读取质感 + 认知矩阵——陌生卡不得发起（F3）、单向知晓不得朋友圈互动（B6/F2）；
- **频率控制台**：三级开关（全局 → 分组 → 单卡覆写）+ 频率档位；发射概率 = 基础频率 × 人设主动度系数 × 关系门槛，人设静默兜底；大事件旁路（无视频率触发一次，仍过接地检查）；
- **见面事件回流**：线下见面结束生成关键事件清单（谁做了什么/给了什么/达成什么约定）注入后续私聊上下文与存储层——治“芒果已送却被当未送”；受官方 [系统记录] 豁免条款约束。

## 第 5 项 · 导演系统 + 群聊 + 摩根斯新闻管道（目标③）

- **导演消息独立通道（H1 根治）**：与用户发言数据层分离。过渡期规范 = 【系统场景说明：…非千岁的发言，角色不可回应或感知此段】+ 真实地名（禁用“A 岛”占位符）。实证补充：【】协议当前双轨并存——状态提取轨正常（13:02 注入 → 13:03 锚点即变“航行中”）、对话回应轨失守（佩罗娜直接怼“你们要去就去呗”），且对推进型事件偶发失守（基德对 14:25/14:41 注入直接响应）——独立通道是根治而非可选；
- **导演系统**：后台任务读状态判断事件触发，旁白注入 + 指定在场卡反应；插曲型 NPC 不建独立卡；
- **群聊 MVP**：共享流水账 + 按卡组装提示词 + 点名制，2-3 卡上限；选角引擎 = 资格筛选（锚点在场/认知资格/剧情必需）→ 权重排序 → 疲劳衰减 + 轮换席 → 两级渲染（台上 3-5 人全量推理，台下轻量模板不跑推理）；
- **摩根斯新闻管道（跨卡传播机制）**：
  - 群聊/多卡剧情结束时导演系统生成“新闻事件条目”（谁、在哪、干了什么）；
  - 按传播延迟与细节衰减规则，以 ② 转述层身份注入其他卡认知（“据报道/传闻……”措辞），不在场角色只知报道版本，知晓层级自动落库进第 3 项矩阵；
  - 摩根斯做功能不做卡（插曲型 NPC 原则）：新闻条目发布者皮套，可附夸张化文风过滤（世界经济学报道风）；
  - 副产品：朋友圈认知边界失效的合规解法——一切跨团知晓必须有报道/转述来源，防幻觉污染条款天然覆盖（贝拉以熟人口吻评论佩罗娜家务事的 F1 类病灶的传播侧治理）；
  - 遗留缺口登记：朋友圈可见性矩阵（谁看得见谁的帖子/评论资格/口吻基线）作者侧无过滤机制，若摩根斯管道不敷日常使用，此处为 P4 后的可选扩展项。

## 施工顺序与验收映射

| 阶段 | 内容 | 验收（复测旧失败项） |
|---|---|---|
| P0 | 第 0 项前置 + 第 1 项加固（含解析容错层） | 429/timeout 压测；无矛盾状态落盘；MiniMax 标签剥离；换模型锚点不断链 |
| P1 | 第 2 项锚点中央登记（含事件已执行标记 + 日程来源分级） | F1 翻案（朋友圈位置 = 锚点；跨港不互动）；贝克曼式脱节消失；幻影见面不再落盘；见面结束不回滚重演 |
| P2 | 第 4 项主动消息治理 | F4/H2/F3/B6 翻案；日程归属标定抽测 |
| P3 | 第 3 项管理台 | 矩阵手动覆写不被改回；翻转有背书；回滚可用；“后天起航”跨日留存 |
| P4 | 第 5 项导演 + 群聊 + 摩根斯 | H1 翻案（独立通道）；群聊事件 → 报道 → 他卡 ② 层知晓全链路 |

P1/P2 可部分并行（管道接地可先注入最近锚点快照）；P3 依赖 P1 落库结构；P4 依赖 P1 + P3。
